# LoRA fine-tuning

## When not to do it

Fine-tuning is the last option. Retrieval quality, prompt wording and a larger
base model are cheaper, faster and reversible. LoRA earns its place when the
model must hold a **format** or **style** that prompting does not reliably
produce — not when it needs to know new facts. Facts belong in the corpus, where
they can be updated without retraining.

## Pipeline

```bash
make finetune-data                                         # 1. build the SFT set
python finetune/train_lora.py --config finetune/configs/lora_qwen3b.yaml   # 2. train
python finetune/eval_lora.py --adapter runs/lora/... --base Qwen/Qwen2.5-3B-Instruct  # 3. judge
python finetune/merge_lora.py --adapter ... --base ... --out runs/merged/...  # 4. export
```

## 1. Dataset

`finetune/prepare_dataset.py` renders every training example **with the same
versioned prompt the service uses at inference time**, and records the prompt ref
and hash in each row's metadata. A mismatch between the training format and the
serving format is the fastest way to make an adapter useless.

Two kinds of example:

- `grounded` — a question, the chunk that answers it plus distractors in
  shuffled order, and an answer that cites the correct source tag. The gold
  source index is recomputed after shuffling, so the model learns to cite what
  it used, not a fixed position.
- `refusal` — an out-of-domain question with unrelated context and the exact
  refusal sentence. This is what teaches the model not to fall back on
  parametric memory.

Questions are derived from heading paths. That is **weak supervision** and the
script says so on every run: for an adapter you intend to ship, replace them with
questions written by hand or generated by a stronger model and then reviewed.

## 2. Training

`finetune/configs/lora_qwen3b.yaml`, with the reason for every non-default value:

| setting | value | why |
| --- | --- | --- |
| `load_in_4bit` / NF4 | on | a 3B model at bf16 is ~6 GB, leaving nothing for activations on an 8 GB card |
| `r` | 16 | rank 8 underfits on a few hundred examples; rank 64 triples adapter size for no measured gain |
| `alpha` | 32 | the conventional `2 × r` |
| `target_modules` | attention + MLP | attention-only adapters underperform on format compliance |
| `gradient_accumulation_steps` | 16 | effective batch 16; 8 GB cannot hold more at 2k context |
| `gradient_checkpointing` | on | ~35% slower, ~40% less VRAM — the trade that makes 8 GB work |
| `optim` | `paged_adamw_8bit` | survives the memory spikes that kill plain AdamW on consumer cards |
| `learning_rate` | 2e-4, cosine, 3% warmup | standard for LoRA; full-fine-tune rates diverge here |

The run writes `run_card.json` next to the adapter: loss, trainable parameter
count and percentage, wall-clock time, peak GPU memory and adapter size. "Did it
fit and how long did it take" is the first question anyone asks when reproducing
a fine-tune.

## 3. Evaluation before promotion

`finetune/eval_lora.py` loads the base model and the adapted model, runs both
greedily over the held-out split, and reports citation rate, refusal rate and
answer length side by side with sample outputs. Greedy decoding is not a style
choice: the comparison has to be reproducible.

Format compliance alone is not sufficient evidence. The promotion rule:

1. format compliance (citation rate, refusal rate) must **improve**;
2. `voicerag eval --judge` faithfulness must not drop by more than 2 points;
3. general answer quality must not visibly regress on the samples.

An adapter that improves formatting while lowering faithfulness is rejected.

## 4. Serving

Adapters are ~35 MB, so they are versioned alongside the code rather than stored
as full model copies. Runtimes that cannot load PEFT adapters at request time
need merged weights — `merge_lora.py` reloads the base at bf16 before merging,
because merging into 4-bit weights silently degrades quality. It prints the
llama.cpp commands for GGUF conversion and Q4_K_M quantization if the target is
Ollama.

weak-supervision examples — far too few for a result worth reporting. The
